# 03 HUD 设计系统（hud_v5_kit.py + hud_v5.py）

## 用户对 HUD 的要求演变（按时间，后者覆盖前者）
1. 取景框不能只是橘色，要跟画面主色变。
2. 要精致，"机能和繁复美"，参考 Raf0x00 原帖（气泡簇、三档线宽、光栅条、刻度尺、镜像小字）。
3. 多用"采样取景"（实时放大窗 + 源处采样框 + 引线），和 HUD 结合。
4. UI 别只有圆 / 矩 / 三角；不要立方体；波形图、蜂巢阵、矩阵可以；雷达少用；取景框外形多样；爆点时 HUD 也 glitch。
5. （v2 后）重合样式太多、像 SVG 图层在平移（自身没 motion）、覆盖时间太长；追踪和画面"不在一个图层"。
6. （v3 后）单帧密度降、覆盖面积大、去掉无用信息、信息清楚有意义、别公式化地堆在一角。→ 做出来的"大面积简单版"被评"有些土"。
7. **最终**："HUD 可以做的精密复杂一些，给人视觉上信息密集的感觉，但是不能太乱"；"HUD 的出现本身就是一套精密的 UI 设计以及融合精致的 motion 和前端设计艺术"；"配色要根据画面和角色的配色来变"。
8. 叠在画面上的召唤法阵"跟画面融合不搭，很像是两个图层" → 不用。

**结论**：密度来自**精密的小元素贴网格排布**（刻度、点阵、边轨、角标、微型数据表），**结构**来自 1–3 个大元素；所有文字是真信息；每个元素有入场 / 退场动效；HUD 和画面同一物理层。

## 设计 token
- 网格：页边 M = 96R，基础间距 U = 8R（R = W/1920）。
- 字阶（Google Fonts，OFL）：DISPLAY = Saira ExtraCondensed Black（巨型字 / 等级字母）；H1 / H2 = Rajdhani Bold / SemiBold（真名、数值）；LABEL = Chakra Petch Medium 全大写字距 0.22em；MICRO = Share Tech Mono；JP = 思源黑 Heavy；宝具名 = Noto Serif Black（明朝 = Fate 宝具名的感觉）。
- 线重：hair 1.2R / line 2R / bold 4R。透明度角色：ink 0.92、dim 0.40、hair 0.25。
- 颜色角色：ink（白微偏主色）、main（角色签名色 × 画面色）、sec、hi、on-accent 近黑、panel 近黑 0.5。

## 动效约定（`Clock`）
- 每个元素 `(t0, dur, order)`：入场 expo-out / back-out；退场按 order 反序在 ~12 帧内收回（后进先出）。
- 线条描边生长（从端点或中点）；面板：框线生长 → 填充 → 标题条横向展开 → 内容；文字：逐字解码（乱码→真字）或逐字上浮；量表逐格步进点亮 + 等级字母回弹；环：分段依次点亮 + 持续慢转；括号：飞入 + 回弹锁定 + 闪两下后变强调色。
- 生命周期（hud_on）：life_in 14 帧；active = max(54, 0.62·镜长)；之后 12 帧退场。爆点镜头立即全显。

## 同一物理层（v3 起）
- 后景层（大环、蜂巢墙、巨型描边字）**世界锁定**：镜头运动相似变换 × 景深系数 0.75–0.95；**被前景人物遮挡**（1/4 分辨率抠像，3 帧平均）。
- 前景层（文字面板）屏幕空间；运动模糊只留 1/4（文字要读得清）。
- GPU 着色器统一：按局部亮度调光、泛光、方向运动模糊、行 glitch、RGB 分离。

设计取向（用户 10-20 否掉 VS 对战牌后）：克制、专业语汇（制图 / 编辑排版 / 测量），不用游戏式对战 UI（VS、PLAYER 1/2、血条式对撞条、巨字）。
歌词避让：dossier / codex / blueprint 的信息在目标远侧 → 逐词歌词和 HUD 式歌词条放目标那一半。

### 目标框要对准（用户 10-20："0:02:39 的 HUD 没有对准人物"）
- 镜头首帧检测 → 光流跟踪。强光 / 小人物 / 一镜多切时检测会锁到光带或整幅 → EDL 里写 `det=["manual"]` + `manual=[x0,y0,x1,y1]`（成片像素）。
- 源片一段里有硬切 / 叠化的（帧差找切点），拆成几条镜头（edl_v12 `SPLIT`）各自取框。
- versus：`vs=dict(keys=[左, 右], pts=[(cx, cy, w, h)…], fixed=True)`（画面比例）；不 fixed 时逐 4 帧人物检测，超过半幅的框丢掉，取不到两个就退回 pts。
- 对不准的镜头宁可不放 HUD（nohud）——先抽帧看括号落点再渲染。

## 公共精密层（chrome，所有模板都有）
四角切口括号；左上作品名、右上曲时间码、左下"CLASS ×× · 宝具种类"、右下最近 32 帧音乐电平条（真实数据）；左 / 上边轨刻度 + 跟随目标坐标的游标三角 + TGT。微元素一律低透明度。

## 信息规则
- 只写核对过的：真名 / 日文名 / 职阶 / 宝具名 + 读音 + 等级 + 种类 / 六项参数（`data/servant_info.json`，FGO Wiki + TYPE-MOON Wiki + Atlas Academy 交叉核对，带来源）。
- 认不出的人物：只写名字和职阶；职阶是占位（"------"）就不写；不确定（"?"）的不当真名用。
- 去掉的无用信息：假坐标、随机编号、"SIGNAL UNSTABLE"、LYR 行号 / 时间码小字、EVA 随机词（承認 / 否決）。
- 歌词避让：dossier / np / type 模板时，逐词歌词换到另一半 / 另一高度；HUD 风格歌词条也换位置。
